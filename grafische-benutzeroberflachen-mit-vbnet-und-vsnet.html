    5. Grafische Benutzeroberflächen mit VB.NET und VS.NET

    Wir möchten hier zeigen, wie man grafische Benutzeroberflächen mit VB.NET erstellt. Zunächst sehen wir uns an, welche Basisklassen der Plattform .NET uns die Erstellung einer grafischen Benutzeroberfläche ermöglichen. Zunächst verwenden wir kein Tool zur automatischen Generierung. Anschließend werden wir Visual Studio.NET (VS.NET) verwenden, ein Entwicklungstool von Microsoft, das die Entwicklung von Anwendungen mit den Sprachen .NET und insbesondere die Erstellung grafischer Benutzeroberflächen erleichtert. Die verwendete Version VS.NET ist die englische Version.

    5.1. Grundlagen grafischer Benutzeroberflächen

    5.1.1. Ein einfaches Fenster

    Betrachten wir den folgenden Code:

    
' Optionen
Option Strict On
Option Explicit On 

' Namensräume
Imports System
Imports System.Drawing
Imports System.Windows.Forms

' Formularklasse
Public Class Form1
    Inherits Form

    ' der Konstruktor
    Public Sub New()
        ' Fenstertitel
        Me.Text = "Mon premier formulaire"
        ' Fensterabmessungen
        Me.Size = New System.Drawing.Size(300, 100)
    End Sub

    ' Testfunktion
    Public Shared Sub Main(ByVal args() As String)
        ' Das Formular wird angezeigt
        Application.Run(New Form1)
    End Sub
End Class

    Der obige Code wird kompiliert und anschließend ausgeführt

    dos>vbc /r:system.dll /r:system.drawing.dll /r:system.windows.forms.dll frm1.vb

dos>frm1

    Bei der Ausführung wird das folgende Fenster angezeigt:

    Eine grafische Benutzeroberfläche leitet sich in der Regel von der Basisklasse System.Windows.Forms.Form ab:

    Public Class Form1
    Inherits Form

    Die Basisklasse Form definiert ein Basisfenster mit Schaltflächen zum Schließen, Vergrößern/Verkleinern, einer anpassbaren Größe usw. und verarbeitet die Ereignisse für diese grafischen Objekte. Hier spezialisieren wir die Basisklasse, indem wir ihr einen Titel sowie eine Breite (300) und Höhe (100) zuweisen. Dies geschieht in ihrem Konstruktor:

    
    Public Sub New()
        ' Fenstertitel
        Me.Text = "Mon premier formulaire"
        ' Fensterabmessungen
        Me.Size = New System.Drawing.Size(300, 100)
    End Sub

    Der Titel des Fensters wird über die Eigenschaft Text festgelegt, die Abmessungen über die Eigenschaft Size. Size ist im Namensraum System.Drawing definiert und stellt eine Struktur dar. Die Prozedur „Main“ startet die grafische Anwendung wie folgt:

    
        Application.Run(New Form1)

    Ein Formular vom Typ Form1 wird erstellt und angezeigt. Anschließend überwacht die Anwendung die Ereignisse, die auf dem Formular auftreten (Klicks, Mausbewegungen usw.), und lässt diejenigen ausführen, die das Formular verarbeitet. In diesem Fall verarbeitet unser Formular keine anderen Ereignisse als diejenigen, die von der Basisklasse Form unterstützt werden (Klicks auf Schaltflächen zum Schließen, Vergrößern/Verkleinern, Ändern der Fenstergröße, Verschieben des Fensters usw.).

    5.1.2. Ein Formular mit Schaltfläche

    Fügen wir nun eine Schaltfläche zu unserem Fenster hinzu:

    
' Optionen
Option Strict On
Option Explicit On 

' Namensräume
Imports System
Imports System.Drawing
Imports System.Windows.Forms

' Formularklasse
Public Class Form1
    Inherits Form

    ' Attribute
    Private cmdTest As Button

    ' der Konstruktor
    Public Sub New()
        ' Titel
        Me.Text = "Mon premier formulaire"
        ' die Abmessungen
        Me.Size = New System.Drawing.Size(300, 100)
        ' eine Schaltfläche
        ' Erstellung
        Me.cmdTest = New Button
        ' Position
        cmdTest.Location = New System.Drawing.Point(110, 20)
        ' Größe
        cmdTest.Size = New System.Drawing.Size(80, 30)
        ' Bezeichnung
        cmdTest.Text = "Test"
        ' Ereignismanager
        AddHandler cmdTest.Click, AddressOf cmdTest_Click
        ' Schaltfläche zum Formular hinzufügen
        Me.Controls.Add(cmdTest)
    End Sub

    ' Ereignis-Handler
    Private Sub cmdTest_Click(ByVal sender As Object, ByVal evt As EventArgs)
        ' Es wurde auf die Schaltfläche geklickt – dies wird gemeldet
        MessageBox.Show("Clic sur bouton", "Clic sur bouton", MessageBoxButtons.OK, MessageBoxIcon.Information)
    End Sub

    ' Testfunktion
    Public Shared Sub Main(ByVal args() As String)
        ' Das Formular wird angezeigt
        Application.Run(New Form1)
    End Sub
End Class

    Wir haben dem Formular eine Schaltfläche hinzugefügt:

    
        ' eine Schaltfläche
        ' Erstellung
        Me.cmdTest = New Button
        ' Position
        cmdTest.Location = New System.Drawing.Point(110, 20)
        ' Größe
        cmdTest.Size = New System.Drawing.Size(80, 30)
        ' Bezeichnung
        cmdTest.Text = "Test"
        ' Ereignismanager
        AddHandler cmdTest.Click, AddressOf cmdTest_Click
        ' Schaltfläche zum Formular hinzufügen
        Me.Controls.Add(cmdTest)

    Die Eigenschaft Location legt mithilfe einer Struktur Point die Koordinaten (110,20) des oberen linken Punktes der Schaltfläche fest. Die Breite und Höhe der Schaltfläche werden mithilfe einer Struktur Size auf (80,30) festgelegt. Mit der Eigenschaft Text der Schaltfläche lässt sich die Beschriftung der Schaltfläche festlegen. Die Klasse „Schaltfläche“ verfügt über ein Click-Ereignis, das wie folgt definiert ist:

    Public Event Click As EventHandler

    wobei EventHandler eine „delegierte“ Funktion mit folgender Signatur ist:

    Public Delegate Sub EventHandler(ByVal sender As Object,ByVal e As EventArgs)

    Das bedeutet, dass der Ereignis-Handler [Click] für die Schaltfläche die Signatur des Delegaten [EventHandler] aufweisen muss. Wenn hier auf die Schaltfläche cmdTest geklickt wird, wird die Methode cmdTest_Click aufgerufen. Diese ist gemäß dem vorherigen Muster EventHandler wie folgt definiert:

    
    ' Ereignis-Handler
    Private Sub cmdTest_Click(ByVal sender As Object, ByVal evt As EventArgs)
        ' Es wurde auf die Schaltfläche geklickt – dies wird gemeldet
        MessageBox.Show("Clic sur bouton", "Clic sur bouton", MessageBoxButtons.OK, MessageBoxIcon.Information)
    End Sub

    5.2.6. Ereignisbehandlung

    Sobald das Formular angezeigt wird, überwacht die Anwendung die Ereignisse, die auf dem Formular auftreten (Klicks, Mausbewegungen usw.), und lässt diejenigen ausführen, die das Formular verarbeitet. In diesem Fall verarbeitet unser Formular keine anderen Ereignisse als diejenigen, die von der Basisklasse Form unterstützt werden (Klicks auf Schaltflächen zum Schließen, Vergrößern/Verkleinern, Ändern der Fenstergröße, Verschieben des Fensters usw.). Das generierte Formular verwendet ein Attribut components, das nirgendwo verwendet wird. Auch die Methode dispose hat hier keine Funktion. Gleiches gilt für bestimmte verwendete Namespaces (Collections, ComponentModel, Data) sowie für den für das Projekt definierten Namespace projet1. Daher lässt sich der Code in diesem Beispiel wie folgt vereinfachen:

    
Imports System
Imports System.Drawing
Imports System.Windows.Forms

Public Class Form1
    Inherits System.Windows.Forms.Form

    ' Konstruktor
    Public Sub New()
        ' Erstellung des Formulars mit seinen Komponenten
        InitializeComponent()
    End Sub

    Private Sub InitializeComponent()
        ' Fenstergröße
        Me.Size = New System.Drawing.Size(300, 300)
        ' Fenstertitel
        Me.Text = "Form1"
    End Sub

    Shared Sub Main()
        ' Die App wird gestartet
        Application.Run(New Form1)
    End Sub
End Class

        AddHandler btnAfficher.Click, AddressOf btnAfficher_Click

    Der obige Code, der in die Prozedur InitializeComponent des Formulars eingefügt wird, ordnet dem Ereignis btnAfficher.Click die Prozedur mit dem Namen btnAfficher_Click zu. Außerdem benötigt die Komponente btnAfficher das Schlüsselwort WithEvents nicht mehr:

    
    Friend btnAfficher As System.Windows.Forms.Button

    Was ist der Unterschied zwischen den beiden Methoden?

    • Mit dem Schlüsselwort „handles“ kann ein Ereignis einer Prozedur nur zum Zeitpunkt der Entwicklung zugeordnet werden. Der Entwickler weiß im Voraus, dass eine Prozedur P die Ereignisse E1, E2, … verarbeiten muss, und schreibt den Code 
    
    Private Sub btnAfficher_Click(ByVal sender As System.Object, ByVal e As System.EventArgs) handles E1, E2, ..., En

    Es ist tatsächlich möglich, dass eine Prozedur mehrere Ereignisse verarbeitet.

    • Mit dem Schlüsselwort `addhandler` kann ein Ereignis zur Laufzeit einer Prozedur zugeordnet werden. Dies ist in einem Produzenten-Verbraucher-Kontext für Ereignisse nützlich. Ein Objekt erzeugt ein bestimmtes Ereignis, das für andere Objekte von Interesse sein könnte. Diese abonnieren das Ereignis beim Erzeuger, um es zu empfangen (beispielsweise eine Temperatur, die einen kritischen Schwellenwert überschritten hat). Während der Ausführung der Anwendung wird der Erzeuger des Ereignisses verschiedene Anweisungen ausführen: 
    Addhandler E, AddressOf P1
Addhandler E, AddressOf P2
...
Addhandler E, AddressOf Pn

    wobei E das vom Produzenten erzeugte Ereignis und Pi die Prozeduren sind, die zu den verschiedenen Konsumentenobjekten dieses Ereignisses gehören. Wir werden in einem späteren Kapitel noch einmal auf eine Produzenten-Konsumenten-Anwendung für Ereignisse zurückkommen.

    C.Remove(object o)

    Private Sub transfert(ByVal l1 As ListBox, ByVal l2 As ListBox)

        If l1.SelectedIndex = -1 Then Return
        ' Hinzufügen zu l2
        l2.Items.Add(l1.SelectedItem)
        ' Löschung in l1
        l1.Items.RemoveAt(l1.SelectedIndex)
    End Sub

    • Ein Schieberegler vom Typ ScrollBar ermöglicht es dem Benutzer, einen Wert aus einem Bereich ganzer Zahlen auszuwählen, der durch den „Streifen“ des Schiebereglers symbolisiert wird, auf dem sich ein Cursor bewegt. Der Wert des Schiebereglers ist in seiner Eigenschaft „Value“ verfügbar.
    • Bei einem horizontalen Schieberegler stellt das linke Ende den Minimalwert des Bereichs dar, das rechte Ende den Maximalwert und der Schieberegler den aktuell ausgewählten Wert. Bei einem vertikalen Schieberegler wird der Minimalwert durch das obere Ende und der Maximalwert durch das untere Ende dargestellt. Diese Werte werden durch die Eigenschaften „Minimum“ und „Maximum“ repräsentiert und sind standardmäßig auf 0 bzw. 100 gesetzt.
    • Ein Klick auf die Endpunkte des Schiebereglers verändert den Wert um einen Schritt (positiv oder negativ), abhängig vom angeklickten Endpunkt mit der Bezeichnung SmallChange, der standardmäßig 1 ist.
    • Ein Klick auf beiden Seiten des Schiebereglers verändert den Wert um einen Schritt (positiv oder negativ), je nach dem angeklickten Ende, das als „LargeChange“ bezeichnet wird und standardmäßig den Wert 10 hat.
    • Wenn man auf das obere Ende eines vertikalen Schiebereglers klickt, verringert sich dessen Wert. Dies kann den durchschnittlichen Benutzer überraschen, der normalerweise erwartet, dass der Wert „steigt“. Dieses Problem lässt sich beheben, indem man den Eigenschaften SmallChange und LargeChange einen negativen Wert zuweist.
    • Diese fünf Eigenschaften (Value, Minimum, Maximum, SmallChange, LargeChange) sind sowohl lesbar als auch beschreibbar.
    • Das wichtigste Ereignis des Umrichters ist dasjenige, das eine Wertänderung signalisiert: das Scroll-Ereignis.

    Eine Komponente mit der Bezeichnung NumericUpDown befindet sich in der Nähe des Umrichters: Auch sie verfügt über die Eigenschaften Minimum, Maximum und Value, deren Standardwerte 0, 100 und 0 sind. Hier wird die Eigenschaft Value jedoch in einem Eingabefeld angezeigt, das fester Bestandteil des Steuerelements ist. Der Benutzer kann diesen Wert selbst ändern, es sei denn, die Eigenschaft ReadOnly des Steuerelements wurde auf „wahr“ gesetzt. Der Wert des Inkrements wird durch die Eigenschaft Increment festgelegt, Standardwert ist 1. Das wichtigste Ereignis der Komponente NumericUpDown ist dasjenige, das eine Wertänderung signalisiert: das Ereignis ValueChanged. Der relevante Code unserer Anwendung lautet wie folgt:

    In unserem Beispiel heißt der Timer timer1 und timer1.Interval ist auf 1000 ms (1 s) eingestellt. Das Ereignis Tick wird daher jede Sekunde ausgelöst. Der Klick auf die Schaltfläche „Stopp/Start“ wird durch die folgende Prozedur verarbeitet:

    
    Private Sub btnArretMarche_Click(ByVal sender As Object, ByVal e As System.EventArgs) _
    Handles btnArretMarche.Click
        ' Aus oder Ein?
        If btnArretMarche.Text = "Marche" Then
            ' Notierung der Startzeit
            début = DateTime.Now
            ' Anzeige der Startzeit
            txtChrono.Text = "00:00:00"
            ' Der Timer wird gestartet
            timer1.Enabled = True
            ' Die Beschriftung der Schaltfläche wird geändert
            btnArretMarche.Text = "Arrêt"
            ' Ende
            Return
        End If        '
        If btnArretMarche.Text = "Arrêt" Then
            ' Timer stoppen
            timer1.Enabled = False
            ' Die Beschriftung der Schaltfläche wird geändert
            btnArretMarche.Text = "Marche"
            ' Ende
            Return
        End If
    End Sub

    Private Sub timer1_Tick(ByVal sender As Object, ByVal e As System.EventArgs) _
    Handles timer1.Tick
        ' Eine Sekunde ist vergangen
        Dim maintenant As DateTime = DateTime.Now
        Dim durée As TimeSpan = DateTime.op_Subtraction(maintenant, début)
        txtChrono.Text = "" + durée.Hours.ToString("d2") + ":" + durée.Minutes.ToString("d2") + ":" + durée.Seconds.ToString("d2")
    End Sub

    Die Beschriftung der Schaltfläche „Stopp/Start“ lautet entweder „Stopp“ oder „Start“. Daher muss ein Test dieser Beschriftung durchgeführt werden, um zu entscheiden, welche Aktion ausgeführt werden soll.

    • Im Fall von „Start“ wird die Startzeit in einer globalen Variablen des Formularobjekts gespeichert, der Timer wird gestartet (Enabled=true) und die Beschriftung der Schaltfläche ändert sich zu „Stopp“.
    • Im Fall von „Stopp“ wird der Timer angehalten (Enabled=false) und die Beschriftung der Schaltfläche auf „Start“ geändert.
