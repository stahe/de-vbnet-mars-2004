    10. Webdienste

    10.1. Einführung

    Im vorigen Kapitel haben wir mehrere TCP/IP-Client-Server-Anwendungen vorgestellt. Da die Clients und der Server Textzeilen austauschen, können sie in jeder beliebigen Programmiersprache geschrieben werden. Der Client muss lediglich das vom Server erwartete Kommunikationsprotokoll kennen. Webdienste sind TCP/IP-Serveranwendungen mit folgenden Merkmalen:

    • Sie werden von Webservern gehostet, und das Protokoll für den Client-Server-Austausch ist daher HTTP (HyperText Transport Protocol), ein Protokoll, das auf TCP-IP aufbaut.
    • Der Webdienst verfügt unabhängig vom angebotenen Dienst über ein Standard-Kommunikationsprotokoll. Ein Webdienst bietet verschiedene Dienste an: S1, S2, …, Sn. Jeder dieser Dienste erwartet vom Client übergebene Parameter und liefert diesem ein Ergebnis zurück. Für jeden Dienst muss der Client Folgendes wissen:
      • den genauen Namen des Dienstes, falls
      • die Liste der Parameter, die bereitgestellt werden müssen, sowie deren Typ
      • den Typ des vom Dienst zurückgegebenen Ergebnisses

    Sobald diese Elemente bekannt sind, folgt der Client-Server-Dialog unabhängig vom abgefragten Webdienst dem gleichen Format. Die Programmierung der Clients wird dadurch standardisiert.

    • Aus Sicherheitsgründen vor Angriffen aus dem Internet verfügen viele Organisationen über private Netzwerke und öffnen nur bestimmte Ports ihrer Server für das Internet: im Wesentlichen Port 80 des Webdienstes. Alle anderen Ports sind gesperrt. Daher werden Client-Server-Anwendungen, wie sie im vorigen Kapitel vorgestellt wurden, innerhalb des privaten Netzwerks (Intranet) aufgebaut und sind in der Regel von außen nicht zugänglich. Die Bereitstellung eines Dienstes auf einem Webserver macht ihn für die gesamte Internet-Community zugänglich.
    • Der Webdienst lässt sich als entferntes Objekt modellieren. Die angebotenen Dienste werden dann zu Methoden dieses Objekts. Ein Client kann auf dieses entfernte Objekt zugreifen, als wäre es lokal. Dadurch wird der gesamte Teil der Netzwerkkommunikation verborgen, und es kann ein von dieser Schicht unabhängiger Client entwickelt werden. Sollte sich diese Schicht ändern, muss der Client nicht angepasst werden. Dies ist ein enormer Vorteil und wahrscheinlich der wichtigste Trumpf der Webdienste.
    • Wie bei den im vorigen Kapitel vorgestellten TCP/IP-Client-Server-Anwendungen können Client und Server in einer beliebigen Sprache geschrieben werden. Sie tauschen Textzeilen aus. Diese bestehen aus zwei Teilen:
      • die für das Protokoll HTTP erforderlichen Kopfzeilen
      • den Hauptteil der Nachricht. Bei einer Antwort des Servers an den Client hat dieser das Format XML (eXtensible Markup Language). Bei einer Anfrage des Clients an den Server kann der Hauptteil der Nachricht verschiedene Formen annehmen, darunter XML. Die Anfrage XML des Clients kann ein spezielles Format haben, das als SOAP (Simple Object Access Protocol) bezeichnet wird. In diesem Fall folgt auch die Antwort des Servers dem Format SOAP.

    Jetzt ist die Sache etwas übersichtlicher.

    • Ein Webdienst ist eine Klasse, die von der Klasse WebService abgeleitet ist
    • Die Klasse wird durch das Attribut <System.Web.Services.WebService(Namespace:="st.istia.univ-angers.fr")> qualifiziert. Wir ordnen unseren Dienst also dem Namensraum st.istia.univ-angers.fr zu.

    10.4. Ein Webdienst für Operationen

    Wir betrachten einen Webdienst, der fünf Funktionen bietet:

    1. add(a,b), das a+b zurückgibt

    Zunächst ist anzumerken, dass wir den Header [Connection: close] hinzugefügt haben, um den Server anzuweisen, die Verbindung nach dem Senden der Antwort zu schließen. Dies ist hier erforderlich. Wenn dies nicht angegeben wird, hält der Server die Verbindung standardmäßig offen. Die Antwort des Servers besteht jedoch aus einer Folge von Textzeilen, von denen die letzte nicht mit einem Zeilenendezeichen endet. Unser generischer Client TCP liest Textzeilen, die mit einem Zeilenendezeichen enden, mit der Methode ReadLine. Wenn der Server die Verbindung nach dem Senden der letzten Zeile nicht schließt, bleibt der Client hängen, da er auf ein Zeilenendezeichen wartet, das nicht kommt. Wenn der Server die Verbindung schließt, wird die Methode ReadLine des Clients beendet und der Client bleibt nicht hängen.

        Dim nbChars As Integer = requête.Length

    Die Methode HttpUtility.UrlEncode(Zeichenkette) wandelt bestimmte Zeichen von chaîne in %n1n2 um, wobei n1n2 der Code ASCII des umgewandelten Zeichens ist. Die von dieser Umwandlung betroffenen Zeichen sind alle Zeichen, die in einer Abfrage eine besondere Bedeutung haben (Leerzeichen, das Gleichheitszeichen =, das Und-Zeichen &, ...). Hier ist die Methode HttpUtility.UrlEncode normalerweise nicht erforderlich, da a und b Zahlen sind, die keines dieser speziellen Zeichen enthalten. Sie wird hier lediglich als Beispiel verwendet.     10.7. Kapselung des Client-Server-Datenaustauschs

    Nehmen wir an, unser Webdienst operations wird von verschiedenen Anwendungen genutzt. Es wäre sinnvoll, diesen eine Klasse zur Verfügung zu stellen, die als Schnittstelle zwischen der Client-Anwendung und dem Webdienst fungiert und den Großteil des Netzwerkverkehrs verbirgt, der für die meisten Entwickler nicht trivial ist. Damit ergäbe sich folgendes Schema:

    Die Client-Anwendung würde sich an die Client-Server-Schnittstelle wenden, um ihre Anfragen an den Webdienst zu stellen. Diese würde den gesamten erforderlichen Netzwerkverkehr mit dem Server abwickeln und das erhaltene Ergebnis an die Client-Anwendung zurückgeben. Letztere müsste sich nicht mehr um den Austausch mit dem Server kümmern, was ihre Programmierung erheblich vereinfachen würde.

        Dim longueur As Integer = 0

        ' Der Wert der Zeile „Content-Length“ wird gespeichert
        ligne = [IN].ReadLine()
        While ligne <> ""
            ' Bildschirmalarm
            If verbose Then
                Console.Out.WriteLine(("<-- " + ligne))
            End If
            ' Content-Length?
            MatchLength = RegexLength.Match(ligne)
            If MatchLength.Success Then
                longueur = Integer.Parse(MatchLength.Groups(1).Value)
            End If
            ' nächste Zeile
            ligne = [IN].ReadLine()
        End While

        ' Ausgabe der letzten Zeile
        If verbose Then
            Console.Out.WriteLine("<--")
        End If

        ' Erstellung des regulären Ausdrucks zum Abrufen des Ergebnisses
        ' im Antwortstrom des Webservers
        Dim modèle As String = "<" + fonction + "Result>(.+?)</" + fonction + "Result>"
        Dim ModèleRésultat As New Regex(modèle)
        Dim MatchRésultat As Match = Nothing

        ' Der Rest der Antwort des Webservers wird gelesen
        Dim chrRéponse(longueur) As Char
        [IN].Read(chrRéponse, 0, longueur)
        Dim strRéponse As String = New [String](chrRéponse)

        ' Die Antwort wird in Textzeilen zerlegt
        Dim lignes As String() = Regex.Split(strRéponse, ControlChars.Lf)

        ' die Textzeilen werden nach dem Ergebnis durchsucht
        Dim strRésultat As String = "?"        ' résultat de la fonction
        For i = 0 To lignes.Length - 1
            ' Weiter
            If verbose Then
                Console.Out.WriteLine(("<-- " + lignes(i)))
            End If            ' comparaison ligne courante au modèle
            MatchRésultat = ModèleRésultat.Match(lignes(i))
            ' Wurde es gefunden?
            If MatchRésultat.Success Then
                ' Das Ergebnis wird notiert
                strRésultat = MatchRésultat.Groups(1).Value
            End If
        Next i

        ' Das Ergebnis wird zurückgegeben
        Return strRésultat
    End Function
End Class

    Dem Konstruktor werden zwei Parameter übergeben:

    1. die URI des Webdienstes, mit dem er sich verbinden soll
    2. einen booleschen Wert verbose, der eigentlich festlegt, dass der Netzwerkverkehr auf dem Bildschirm angezeigt werden soll; andernfalls erfolgt keine Anzeige.

    Während der Erstellung werden die Datenströme IN für den Netzwerk-Lesezugriff, OUT für den Netzwerk-Schreibzugriff sowie das Verzeichnis der vom Dienst verwalteten Funktionen erstellt. Sobald das Objekt erstellt ist, wird die Client-Server-Verbindung geöffnet und die Datenströme IN und OUT stehen zur Verfügung.

    Mit der Methode Close lässt sich die Verbindung zum Server schließen.

    Die Methode ExecuteFonction ist diejenige, die wir für den untersuchten Client SOAP geschrieben haben, bis auf einige Details:

    1. Die Parameter `uri`, `IN` und `OUT`, die zuvor als Parameter an die Methode übergeben wurden, müssen nun nicht mehr übergeben werden, da sie nun Instanzattribute sind, auf die alle Methoden der Instanz zugreifen können
    2. Die Methode ExecuteFonction, die zuvor einen Typ void zurückgab und das Ergebnis der Funktion auf dem Bildschirm anzeigte, gibt nun dieses Ergebnis und somit einen Typ string zurück.

    In der Regel wird ein Client die Klasse clientSOAP wie folgt verwenden:

    1. Erstellung eines Objekts vom Typ clientSOAP, das die Verbindung zum Webservice herstellt
    2. wiederholte Verwendung der Methode executeFonction
    3. Schließen der Verbindung zum Webdienst mithilfe der Methode Close.

    Public Class operations

    Die Klasse trägt den Namen operations des Webdienstes, für den sie erstellt wurde. Sie leitet sich von der Klasse SoapHttpClientProtocol ab:

    Unsere Proxy-Klasse verfügt über einen einzigen Konstruktor:

    Der Konstruktor weist dem Attribut url den Wert URL des mit dem Proxy verbundenen Webdienstes zu. Die oben genannte Klasse operations definiert das Attribut url nicht selbst. Dieses wird von der Klasse geerbt, von der der Proxy abgeleitet ist: System.Web.Services.Protocols.SoapHttpClientProtocol. Sehen wir uns nun an, was sich auf die Methode ajouter bezieht:

        Public Function ajouter(ByVal a As Double, ByVal b As Double) As Double

        Return CType(results(0),Double)

          <WebMethod>  _
      Function ajouter(a As Double, b As Double) As Double
         Return a + b
      End Function 'ajouter

    Die Art und Weise, wie diese Klasse mit dem Webdienst kommuniziert, wird hier nicht dargestellt. Diese Kommunikation wird vollständig von der übergeordneten Klasse System.Web.Services.Protocols.SoapHttpClientProtocol übernommen. Im Proxy findet sich nur das, was ihn von anderen Proxys unterscheidet:

    10.9. Einen Webdienst konfigurieren

    Ein Webdienst benötigt möglicherweise Konfigurationsinformationen, um ordnungsgemäß initialisiert zu werden. Beim Server IIS können diese Informationen in einer Datei namens web.config gespeichert werden, die sich im selben Ordner wie der Webdienst befindet. Angenommen, man möchte einen Webdienst erstellen, der zur Initialisierung zwei Angaben benötigt: einen Namen und ein Alter. Diese beiden Angaben können in der Datei „web.config“ in folgender Form hinterlegt werden:

    <?xml version="1.0" encoding="UTF-8" ?>
<configuration>
  <appSettings>
    <add key="nom" value="tintin"/>
    <add key="age" value="27"/>
  </appSettings>   
</configuration>

    Die Initialisierungsparameter werden in einem Umschlag mit der Kennung XML abgelegt:

    <configuration>
    <appSettings>
...
    </appSettings>
</configuration>

    Ein Initialisierungsparameter mit dem Namen P und dem Wert V wird mit folgender Zeile deklariert:

    
        <add key="P" value="V"/>

    Wie ruft der Webdienst diese Informationen ab? Wenn IIS einen Webdienst lädt, prüft er, ob sich im selben Ordner eine Datei mit dem Namen web.config befindet. Ist dies der Fall, liest er sie ein. Der Wert V eines Parameters P wird durch die Anweisung ermittelt:

            String P=ConfigurationSettings.AppSettings["V"];

    wobei ConfigurationSettings eine Klasse im Namensraum System.Configuration ist.

Option Explicit On 
Option Strict On

' Namensräume
Imports System
Imports Microsoft.VisualBasic

' Test-PG
Module testimpots
    Sub Main(ByVal arguments() As String)
        ' Interaktives Programm zur Steuerberechnung
        ' Der Benutzer gibt drei Daten über die Tastatur ein: verheiratet nbEnfants Gehalt
        ' Das Programm zeigt daraufhin die zu zahlende Steuer an
        Const syntaxe1 As String = "pg DSNimpots tabImpots colLimites colCoeffR colCoeffN"
        Const syntaxe2 As String = "syntaxe : marié nbEnfants salaire" + ControlChars.Lf + "marié : o pour marié, n pour non marié" + ControlChars.Lf + "nbEnfants : nombre d'enfants" + ControlChars.Lf + "salaire : salaire annuel en F"

        ' Überprüfung der Programmparameter
        If arguments.Length <> 5 Then
            ' Fehlermeldung
            Console.Error.WriteLine(syntaxe1)
            ' Ende
            Environment.Exit(1)
        End If        'if
        ' Die Argumente werden abgerufen
        Dim DSNimpots As String = arguments(0)
        Dim tabImpots As String = arguments(1)
        Dim colLimites As String = arguments(2)
        Dim colCoeffR As String = arguments(3)
        Dim colCoeffN As String = arguments(4)

        ' Erstellung eines Steuerobjekts
        Dim objImpôt As impôt = Nothing
        Try
            objImpôt = New impôt(DSNimpots, tabImpots, colLimites, colCoeffR, colCoeffN)
        Catch ex As Exception
            Console.Error.WriteLine(("L'erreur suivante s'est produite : " + ex.Message))
            Environment.Exit(2)
        End Try

        ' Endlosschleife
        While True
            ' zunächst keine Fehler
            Dim erreur As Boolean = False

            ' die Parameter für die Steuerberechnung werden abgefragt
            Console.Out.Write("Paramètres du calcul de l'impôt au format marié nbEnfants salaire ou rien pour arrêter :")
            Dim paramètres As String = Console.In.ReadLine().Trim()

            ' Was ist zu tun?
            If paramètres Is Nothing Or paramètres = "" Then
                Exit While
            End If

            ' Überprüfung der Anzahl der Argumente in der eingegebenen Zeile
            Dim args As String() = paramètres.Split(Nothing)
            Dim nbParamètres As Integer = args.Length
            If nbParamètres <> 3 Then
                Console.Error.WriteLine(syntaxe2)
                erreur = True
            End If
            Dim marié As String
            Dim nbEnfants As Integer
            Dim salaire As Integer
            If Not erreur Then
                ' Überprüfung der Gültigkeit der Parameter
                ' verheiratet
                marié = args(0).ToLower()
                If marié <> "o" And marié <> "n" Then
                    Console.Error.WriteLine((syntaxe2 + ControlChars.Lf + "Argument marié incorrect : tapez o ou n"))
                    erreur = True
                End If
                ' nbEnfants
                nbEnfants = 0
                Try
                    nbEnfants = Integer.Parse(args(1))
                    If nbEnfants < 0 Then
                        Throw New Exception
                    End If
                Catch
                    Console.Error.WriteLine(syntaxe2 + "\nArgument nbEnfants incorrect : tapez un entier positif ou nul")
                    erreur = True
                End Try

                    End If

        End While
